# `_tasks/` —— 任务卡（共享黑板的写入端）

**规矩：任何 agent 接活之前，先读本目录里对应的卡，不靠口头转述。**

## 为什么要有这个目录

以前派活靠我在对话里把任务讲一遍，问题是：

1. **任务书只活在我的上下文里** —— 我一停，接不上；
2. **结论经过我转述** —— 你看到的是我的话，不是原话；
3. **判据靠我复述** —— 我漏一句、或者我自己理解歪了，审稿人审的就不是同一件事。

⇒ 这一目录的作用就是**把任务书和判据从我的上下文里搬出来**。

## 一张卡长什么样

照 `_tasks/TEMPLATE.md` 抄。必填四项：

| 字段 | 为什么必填 |
|---|---|
| **判据** | 没有判据，审稿人只能凭"看起来对不对"给意见，那是回声不是审查 |
| **只读哪些文件** | DSH 现在是 `danger-full-access`，提示词是唯一的约束 |
| **不许改任何文件** | 审稿结论一律走 `_reviews/`，让它动代码就没有独立取证了 |
| **怎么算完成** | 落盘 + 字节数，不看它自报 |

## 卡里不许写什么

- **不许写我的结论**。写了审稿人就顺着说，等于花钱买回声。
- **不许写"我认为这里有问题"**。要它自己判断。

例外：明确要求反驳某一判断时（对抗评审模式），那就**必须**把我的判断写全，
并附一句"如果你为了鼓励我而抬高结论，对我是负分"。

## 生命周期

```
写卡 → 同时派给 cc 和 DSH（互不知情）→ 各自写 _reviews/<名字>.md → 你看分歧项
```

- 卡写完不动。要改判据就写新卡，不改旧的（否则审稿人对不上你在审什么）。
- 一张卡可以派给多轮；每轮结论是独立文件，不覆盖。
