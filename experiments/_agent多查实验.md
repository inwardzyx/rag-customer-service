# 实验：Agent 式多查能不能救回拒答题（2026-10-10）

分支 `feat/agent-multi-search`，脚本 `experiments/agent_multi_search.py`。
**主流程一行没改** —— 这个实验只在脚本里搭了一个对照。

## 一、要回答的问题

上一轮结论：q16/q20 是**答案形态不匹配**（问"学费标准"，库里只有"学费减免额度"）。
那自然会想：**如果让模型自己再查几次，是不是就能找到了？**

这是把 RAG 从第三类（硬编码流水线）往第二类（Agent 式自主决策）跳的**最小改动**：
把 `search` 变成模型可调用的 tool，让它自己决定"要不要再查、换什么查"。

所以判据不是"代码里有没有 while"，而是：**多查一次到底能不能救回那两道题。**

## ★ 判读标准（实验前就写死，防止事后找理由）

| 结果 | 结论 |
|---|---|
| 救回 q16/q20 **且**对照组三道仍拒答 | 多查有判别力，值得接进主流程 |
| 一道都没救回 | 库里真没有，多查只是烧 token，接进去是**净亏** |
| 对照组被误放行 | 多查没有判别力，它在乱翻，接进去会**制造幻觉** |

三条都写在脚本里，跑完自动对照。

## 二、怎么搭的"Agent"

关键点：**查询词必须是模型自己给的，不能是我预设的同义词表。**

用同义词表（"学费"→"费用/收费/标准"）不是 Agent，只是把 `if-else` 换成了 `dict` 查表——
顺序还是我写死的。Agent 的判据是**下一步做什么由模型根据当前情况自己决定**。

所以每轮只给模型三样东西：原问题、这一轮查到了什么、每块精排多少分。然后问它：
"资料里有没有【能直接回答】这个问题的？顺便给下一个查询词。"

★ 判断标准写进了 prompt：**不是"像不像"，而是"有没有用户问的那个值"**
（问"多少钱"必须有金额，问"几天"必须有时间值，资料只是提到相关主题但没给值 = 没有）。

上限 3 轮，且**同一查询词不查第二次**（防模型卡在一个词上烧 3 次钱）。

## 三、实测结果

```
题     现状          多查后         变化
q16    拒（3分）      拒（最高4分）   不变
q20    拒（0分）      拒（最高1分）   不变
q15    拒（0分）      拒（最高0分）   不变  ← 对照组
q17    拒（0分）      拒（最高0分）   不变  ← 对照组
q19    拒（0分）      拒（最高9分）   不变  ← 对照组，见下

救回 0 道，误放行 0 道
```

**⇒ 落在第二档：一道都没救回。多查只是烧 token。**

## ★★ 但最有价值的数据是 q16 的 3 → 3 → 4

模型自己把查询词换到了「学费 收费标准 每学年 元」，分数**涨了 1 分**。
说明**换角度确实有用**——只是没用够。差的那 1 分去哪了？

我把 4 分那条块的原文和理由打出来了：

```
「专项补助管理办法.md｜第七条」  4 分
理由：涉及新生学费资助，与学费相关，但非本科生学费收费标准。
原文：……主要用于资助家庭经济特别困难的新生缴纳第一学年学费，
      资助标准最高不超过 6000 元，学费标准低于 6000 元的，
      按实际应缴纳学费金额进行资助。
```

**库里所有沾"学费"的条款，它全查到了，一条不漏**：

| 条款 | 内容 | 是不是答案 |
|---|---|---|
| 专项补助第七条 | 新生资助最高 6000 元，**且学费低于 6000 按实缴资助** | 不是（这是资助上限） |
| 专项补助第九条 | 减免一学年学费／减免一半 | 不是（这是减免额度） |
| 应征入伍第二十八条 | 退役士兵学费资助最高 8000 元 | 不是（军人专属） |
| 全日制奖助学金第五条 | 国家奖学金 10000 元 | 无关 |
| 学生奖励第十五条 | 学院奖学金 3000/2000/1000 | 无关 |

⇒ **库里确实没有"学费标准"这个值。多查三轮已经把它能沾的都沾完了。**

★ 这同时**再次证实**（第二次）我上一轮那个修正：
`第九条`写的是"减免一学年学费／减免一半学费"，问的是**学费的减免额度**，
而 q16 问的是**学费本身的金额**。
**库里没有的是"学费项目的金额"，不是"没有金额"** —— 这个判断经得起多查验证。

## ★★ 第二个意外收获：q19 的 9 分

对照组里 q19「宿舍几点熄灯」第二轮拿到**精排 9 分**，第三轮 8 分——
但模型仍然判定"还没找到"，拒答正确。

**为什么 9 分还拒答？** 因为那是 `学生纪律处分｜第三章-第十八条（一）`，
讲的是"学生应当遵守学校作息时间"——**它给了 9 分是因为"作息"和"几点熄灯"语义很近，
但里面没有时间值**。

这说明两件事：
1. **主流程那个"精排 < 5 就拒"的硬阈值，在这条边界题上失效了**：
   9 分会被放行，然后模型拿着一条没有时间值的条款去编答案。
   ★ 换句话说：**在线层 5/5 那个成绩有个隐藏条件** —— 它只在
   "精排 prompt 同时要求判断 answerability"时成立。本实验的判据 prompt
   加了"有没有那个值"的要求，于是 9 分被正确压住了。
   ⇒ 这条是我做完实验才发现的**对上一轮结论的一个限定条件**，不是推翻。
2. **更强的判据 prompt 能救边界题，但不该靠改阈值救。**
   把阈值从 5 调到 9 会把q3、q18 那些正常题一起误杀。

## 四、结论（分三句）

1. **多查救不了 q16/q20** —— 库里真没有，多查三轮只是烧 token（15 轮调用，
   每次一个 rerank + 一个判据调用）。
2. **多查没有制造幻觉** —— 对照组三道全部仍然拒答，包括那道拿到 9 分的。
   这一点比第1 条更重要：**它证明了这个判据 prompt 本身是可靠的**，
   只是可靠地得出了"确实没有"的结论。
3. ★ **真正的收益不在"多查"，在"判据 prompt 变严"。**
   本实验里让模型判断"有没有那个值"之后，连 9 分的干扰项都被压住了。
   ⇒ 如果要改进，**该改的是主流程 rerank 的 prompt（加answerability 判据），
   而不是加循环**。加循环只是把成本翻 3 倍，换来 0 个救回。

## 五、那"从第三类跳到第二类"还做不做

**做，但不是靠循环，靠别的。**

这个实验恰好证明了**"加 while 循环"是最差的一条跳法**：它把成本翻 3 倍，
换来 0 个救回，还多了一个"模型卡在同一个查询词上"的失败模式
（我在代码里防了这道，但那是补丁不是能力）。

真正能体现"自主决策"、且这个项目用得上的改动，按性价比排：

| 改动 | 体现什么| 有实测支撑吗 |
|---|---|---|
| rerank prompt 加 answerability 判据 | 模型判断"有没有取值"而非"像不像" | ★ 本实验已验证（压住 9 分干扰项） |
| 多轮里保留上一轮的"已排除"信息 | 状态管理（Agent 的真特征） | 本实验的15 个查询词已展示它每次都在重复已排除的方向 |
| 多跳拆分（把"学费标准"拆成"学费"+"标准"分别查） | 自主规划查询 | 需要先有查询规划器，属于下一阶段 |

★ 那个"重复已排除方向"的现象值得单独记：15 个查询词里，
q19 那道模型换了两轮仍在查「宿舍作息时间」的同义表达。
**这正是 Agent 需要显式状态的地方** —— 没有"已经查过什么、结论是什么"的记录，
模型就会重复劳动。这比"能不能找到"更值得讲，因为它展示的是 Agent 的**本质需求**，
不是本项目的功能需求。
