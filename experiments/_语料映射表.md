# experiments 教学脚本的校园语料映射表（改写基准 + 改完实测结果）

改写日期：2026-10-09。主服务 `docs/kb/` 已在 2026-09 从虚构电商切成真实校规
（2 篇：学生请销假制度、学生纪律处分管理规定，68 个条款块），
本文件记录 `experiments/` 下教学脚本同步改写的**依据、做法与实测结果**。

> ★ 保留这份文档的理由：换语料不是"改几个词"，它牵动阈值、断言和跨文件一致性。
> 下次再改语料前先读这份，省得重新踩一遍。

## 一、为什么教学脚本不能"随便换成随便的校园条款"

三处必须用**能触发同样效果**的素材，换别的就演示失效：

| 演示目的 | 不能随便换的原因 | 实际怎么做的 |
|---|---|---|
| **关卡1 太短碎屑** | ★ 实测真实校规最短22 字，<15 字的块数 = 0。直接搬 `docs/kb/` 会让关卡1 打出"拦下 0 块"，演示直接消失 | 人工写两条短条款：`见附件。`（4 字）、`（见下表）`（5 字）|
| **关卡3 近似重复** | 阈值 0.90 和两个实测值**是从那对电商文本算出来的**。换文本不测阈值 = 阈值失效 | 自己写一对"改几个字"的同义条款（"事假须由家长与班主任联系并说明情况后…" vs "事假需要家长与班主任联系说明情况…"），**跑脚本测出 0.968 再回填** |
| **关卡4 PII** | 三个正则只认数字模式，与语义无关，但需要保留"一段文本塞 2 种 PII"的性质 | `学生张明，学号 2024010101，手机号 13812345678，身份证号 440301199001011234` |

## 二、文档名映射：10 份 → 6 份

step4 原来有 10 份虚构文档。校园版**不凑满 10 份** —— 手头只有 2 篇真实校规，
硬凑出来的"奖学金办法"会是假的，而假语料恰好是这个项目最早被批评的点
（README 里"虚构电商语料"那段历史）。6 份正好与 `rag_concepts_demo.py` 对齐。

★ 6 份文档全部**从真实校规条款改写**，保留格式硬约束：

step4 的「块数」「硬切 vs 递归切」对比叙事全部作废。

## 六、★ 顺手修掉的两个真 bug（改写过程中发现的，不在原计划里）

### ① 7 个教学脚本缺 `env_compat.ensure_uuid_utils()` —— 本机根本跑不起来

本机应用控制策略拦掉 uuid_utils 的 DLL，凡 import langchain/langgraph 的脚本都会
`ImportError` 起不来。搬进仓库前就存在（不是改写引入的），
但「跑一遍验证」这个动作把它暴露了出来。

已补上的文件（调用顺序必须在 `import langchain_*` 之前）：
`step1` / `step2` / `step3` / `step5` / `step6` / `rag_concepts_demo` /
`langgraph_basics/first_real_llm` / `langgraph_basics/langgraph_toolnode_demo` /
`langgraph_persistence/langgraph_deploy_langsmith_demo`。

★ 同时发现**子目录里的文件需要三层 `dirname`** 才能指到仓库根
（`langgraph_basics/`、`langgraph_memory/`、`langgraph_hitl/`、`langgraph_persistence/`），
顶层文件两层即可。

### ② `step4` 的 faiss 探测是假的 —— `try: import faiss` 拦不住策略拦截

原代码 `try: import faiss` / `HAVE_FAISS = True`，但被应用控制策略拦掉 DLL 时，
**`import` 会成功、模块属性却是空的**，于是 `faiss.IndexFlatIP` 抛 `AttributeError`，
而 `try/except` 只包住了 import 那一步，抓不到后面的 AttributeError。

改成**真正用一次**才算探测成功：

```python
import faiss
_probe = faiss.IndexFlatIP(1)      # ← 真正试一次：造个 1 维索引
del _probe
HAVE_FAISS = True
```

⇒ 这跟 pytest 那个 `uuid_utils` 插件是同一类问题：
**"能力要装在入口早的地方"**。光检查"能不能 import"不够，要检查"用起来会不会炸"。

## 七、还留着的一处「刻意不改」

`langgraph_hitl/langgraph_interrupt_min2.py` 里原来的「装箱发货」是**工厂流水线隐喻**
（备料 → 质检 → 装箱发货），不是电商语料。已改成「封装归档」保持流水线意象，
但要记住：**不是所有带"发货"字样的地方都该改**，判断依据是"它在讲电商规则吗"。
