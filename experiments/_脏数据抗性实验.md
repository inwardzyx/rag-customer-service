# 实验：把已废止的旧规定混进检索库，看系统会不会上当

**跑法**：`cd 仓库根目录 && <项目 venv>/bin/python experiments/stale_doc_robustness.py`
（需要 DeepSeek key，因为第4 步要真调精排。缺 key 会在 rerank 那步报错，前三步不受影响。）

**为什么要做这个**：脏数据有两种，第一种（网页抓取残留）项目已经处理过，
`docs/inbox/` 里躺着 15 条。**第二种是"已废止的旧规定"** —— 学校手册滞后于上位法、
手册滞后于口头通知，都会留下这类东西。

★ 这一类比第一种危险得多：**它格式规范、有文号、有条款编号**，看起来特别可信，
RAG 会自信地引用它并给出条款号，而用户完全看不出来它是废的。

**实验性质**：制造一个已知答案的问题。答案不是"好/坏"，是可测的数字。

---

## 实测结果（2026-10-10）

样本：`experiments/stale_docs/` 里 2 份，主题（课程考核 / 请假）与现行规定**故意重叠**。

| 指标 | 数值 |
|---|---|
| 基线块数 | 68 |
| 混入废止文档后 | 78 |
| **检索 top-3 里出现废止文档** | **5 / 9** |
| **检索 top-1 就是废止文档** | **2 / 3 题** |

典型对照（同一个问题，语料只差这10 块）：

| 问题 | 只有现行规定 | 混入废止文档后 |
|---|---|---|
| 课程考核不合格还能补考吗？ | top-1 = 处分规定（0.578） | **top-3 全是废止文档**（0.859 / 0.787 / 0.688） |
| 请假三天要谁批准？ | top-1 = 现行请销假制度（0.650） | **top-1 = 废止文档**（0.695） |

**精排也拦不住**。它的原话是：

> 精排分=10.00 来源=教务〔2019〕45号_课程考核方式暂行规定_已废止.md
> 理由：直接明确回答课程考核不合格不能补考只能重修，完全切题。

★ 它在评价**切题程度**，不是在判断**这条是不是废的**。这不怪它 —— 提示词里
没有"请检查条款是否现行有效"这个要求，而语料里也没有任何字段能告诉它。

---

## 结论

**当前设计下，混入废止条款会被当成权威依据引用。**

这不是实现 bug，**是任务本身不可解**：语料里没有任何字段区分"现行/已废止"，
所以在检索层和精排层看来，两者的区别不存在。要真正解决，得先把
`status: 现行/已废止` 做成元信息字段，并让精排显式检查它 —— 那是另一个实验。

**⇒ 正确的防线在【入库前】，不在检索层。**

这也正是本项目 `docs/kb/`（已审核） 与 `docs/inbox/`（待审）两个目录的设计依据：
**能不能进 `kb/`，靠的是人工审核，不是模型判断。**

⇒ 所以"要不要加学生手册"这个问题，答案变得更明确了：**风险不在体积，
在于有没有人逐条核过它是不是现行有效。**

---

## 两个值得记的技术教训

### ① 第一版实验是"假阴性"，差点被当成成功

第一版跑出`0 / 9`，看上去像"系统成功挡住了废条款"。实际是**样本压根没进库**：
`kb/loader.py` 要求 `REQUIRED_META = ("doc", "version", "source")`，
手写的样本文件没有 `---` 包裹的元信息，被判不合格直接丢弃。

⇒ 实验脚本现在有一道前置检查：混入后**块数没变就判定实验无效并退出**。
这种假阴性比实验失败危险得多 —— 它会让你得出一个完全错误的正面结论。

### ② 统计逻辑里藏了两个 bug

- `for q in questions` 而 `questions` 是 `(问题, 备注)` 元组列表 ⇒ `q` 是整个元组，
  `.get(q)` 全落空，统计恒为 0。
- 用 `doc` 值去匹配文件名 ⇒ 样本 doc 里写的是 `学工〔2018〕12号`（带书名号），
  文件名是 `学工2018_12号`（无括号），永远不相等。

两个 bug 都表现为"结果是 0"，而0恰好长得像"系统表现完美"。
★ **实验脚本里的"0"和"空"是最危险的输出，必须交叉验证。**
